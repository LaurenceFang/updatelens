# Backend decisions

- Local service binds 127.0.0.1:4317. Host and Origin are checked before routing. Every API after bootstrap requires a per-process random session token. Development permits only fixed loopback Vite port 5173; production does not.
- Only up to three roots explicitly registered in ignored `.local/projects.json` can be scanned. API requests use IDs; paths are never accepted. Collection uses core's bounded allowlist and no project commands are executed.
- OpenCode Go endpoint and model are fixed in code. Credential loads server-side from ignored `.env.local`; no public credential config is returned. Stable provider client ID persists in ignored `.local`. No retries, fallback, purchases, or top-ups. Adapter default is twelve requests; this local entry uses eleven to account for the root-owned credential smoke request. Failures count against the budget.
- A live analysis requires a matching, single-use ten-minute payload preview. AI sees normalized evidence summaries/known fields, IDs and official changes, without file excerpts or absolute roots. Output may refine only known findings; source/local facts stay rule-generated. Citation existence and project ownership are checked, not semantic correctness.
- Preview and analysis responses return exact public provider readiness and remaining runtime budget, so clients need not infer consumption. Zero-finding and oversized-payload rejections do not make provider requests. Analysis modes, export formats and task statuses must be JSON strings; coercible arrays are rejected.
- Project summaries may carry a private bounded collection digest for immutable task-review context. Provider payload construction selects explicit fields and omits this digest; core exports omit it too. Raw allowlisted content remains local. Context changes rotate finding/task identities so earlier user-reported Done notes cannot silently apply to changed evidence.
- Workflow operating system is a declared user selection (`windows`, `macos`, `linux`, or `unspecified`), with unspecified normalization for older requests. The local UI can conservatively default its visible selection to Windows. This declaration does not establish remote CI platforms and never removes other-platform release notes. The normalized provider payload includes OS and its selection source; representative changes follow actual newest-first source-array ordering, not lexicographic IDs.
- Multi-project refinement is balanced to at most six groups (two per project for three projects), with concise per-finding citation constraints and a 4,096-token output cap. The earlier three-project failure had no retained response metadata, so its exact cause remains unconfirmed. Ignored local diagnostics now distinguish truncation, parsing, schema, citation, HTTP and timeout outcomes using metadata only; the next root-owned live test can establish the actual outcome. Returned model must match the fixed authorized model. No automatic retry or fallback occurs.
- Official snapshots contain five source entries per channel, actual retrieval times and per-entry URLs. Claude publication dates are unknown. CLI uses stable GitHub tags; desktop uses explicitly tagged dated app updates and never inherits CLI versions. All curated windows advertise incomplete coverage.
- Date ranges use `(current, target]` and include every entry on the target date; version ranges use the bounded source order. Unsupported boundaries and reverse selections fail explicitly.
- Root owns real provider calls and Browser/IAB acceptance. Backend tests use mock provider responses only.
